## 今日总结

这讲把 K8s 的「为什么」讲透了：编排平台的价值就三件事——把容器放到合适的地方（调度）、坏了自动挪走（自愈）、忙了自动加人（伸缩）。架构上记住两条：所有组件只跟 API Server 说话，K8s 自己不碰网络和存储（交给 CNI / CSI 插件）。实操层面最值得记的是「同一个对象换份 YAML 再 apply 就完成升级扩容」——声明式 API 的直观体现。
