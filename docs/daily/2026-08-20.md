## 问题与解决
- **问题**：dfdaemon 日志里出现 `proxy HTTPS request directly to remote server`，担心 P2P 没生效。
- **解决**：这是 manifest（清单）直连通道，属正常行为；manifest 小且须字节精确，不值得 P2P。真正加速在 layer blob，判定看 blob 是否出现 `from parent "...seed-peer..." using protocol tcp`。两行日志并存 = 健康状态。

- **问题**：bran-gr2 上拉镜像后隔几小时 `tail` 日志，看不到 P2P 下载记录，怀疑加速没生效。
- **解决**：节点已缓存该镜像 → 重拉走缓存不触发 blob 下载；且 dfdaemon/nydus pod 会重启 + 日志每 15min evict 滚动。正确姿势 = 换未缓存节点 + 当场 `kubectl logs -f` 实时跟。最终在 172.16.2.54 实时抓到 seed-peer TCP 分片日志，证 P2P 生效。

## 今日总结
系统梳理了 Dragonfly 镜像加速的原理与验证方法：镜像加速 = Dragonfly(P2P) + Nydus(懒加载)；dfdaemon 拦截 containerd 请求，manifest 直连、blob 走 P2P；在 TCE bran-gr2 实测跑通 P2P（seed-peer 经 TCP 分发分片）。同时厘清 TCE 环境坑（clusters CRD 非 mcls、kubeconfig 分离、节点标签打业务集群、containerd 1.6.9 不支持 Nydus）。沉淀为可复用的验证 SOP 与项目侧配置/前端校验约定。
