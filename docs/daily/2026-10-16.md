## 问题与解决

- **问题**: `kubectl get pods -A` 里 coredns / 业务 Pod 一直 `ContainerCreating`，事件报 `failed to find plugin "loopback" in path [/opt/cni/bin]`。
- **根因**: `containerd config default` 生成的配置默认 CNI `bin_dir = /opt/cni/bin`，但 TencentOS 的 CNI 插件实际装在 `/usr/libexec/cni/`，containerd 找不到插件导致 Pod 网络沙箱创建失败。
- **解决**: `for f in /usr/libexec/cni/*; do ln -sf "$f" /opt/cni/bin/$(basename "$f"); done` 把标准插件软链过去。

## 今日总结

从零用 kubeadm 在一台 TencentOS 机器上部署了单节点 K8s 集群（v1.32.13 + containerd + flannel），并系统理清了网络底层：三种 IP 的区别、Service 端口三件套、CNI 标准与 flannel 实现的关系、以及 cni0/flannel.1/veth 这些虚拟网卡各自的作用。核心收获是「虚拟网卡只是 Linux 的软件特性」——K8s 不需要多买网卡，靠软件造出虚拟网络就能让 Pod 像独立电脑一样互相通信。踩的坑是 containerd 的 CNI 插件路径在不同发行版不一致，生成默认配置后要核对 bin_dir。
