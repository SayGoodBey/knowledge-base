# 2026-11-19 学习日志

## 知识点

- [前端/构建工具] tce dev 热更失效排查：fsevents@1 段错误 + CSP 拦截 `__webpack_hmr` → 详见 [构建工具](/topics/frontend/build-tools/)
- [前端/构建工具] macOS FSEvents 与 Node `fs.watch` 文件监听的区别

## 问题与解决

- **问题**: `tce dev` 改代码不生效，必须重启
  - **根因**: tce-cli 依赖的 `fsevents@1.2.13` 在 arm64 + Node 18 上段错误（exit 139），dev server 不退出但文件监听失效
  - **解决**: 把全局 tce-cli 下的 `node_modules/fsevents` 改名禁用，chokidar 自动回退 `fs.watch`；重启 dev server
- **问题**: 浏览器 `http://wds.tea.local/__webpack_hmr` 一直红、Provisional headers
  - **根因**: 页面 CSP 的 `connect-src` 拦截 SSE 长连接（script 不受影响，所以 JS 能加载）
  - **解决**: whistle 加 `<控制台域名> disable://csp`
- **干扰项**: `hot update failed for module ...react-hot-loader/root.js` 是 react-hot-loader 100ms 计时器误报，可忽略

## 今日总结

热更链路分"服务端监听 → 编译 → SSE 推送 → 浏览器拉取替换"几段，排查时先用 curl 监听 `__webpack_hmr` + touch 文件，区分是服务端没编译还是浏览器没收到，再分别下钻。
