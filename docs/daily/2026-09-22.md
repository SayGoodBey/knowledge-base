## 问题与解决

### 问题：CI `tnpm install` 阶段挂在 esbuild postinstall

**现象**:

```
npm ERR! path /data/source/packages/tke/node_modules/esbuild
Error: Expected "0.25.5" but got "0.16.17"
    at validateBinaryVersion (install.js:135)
```

**排查过程**（走了几段弯路）:

1. **误判 1**：以为在 `packages/tke/package.json` 加 `overrides.esbuild` 能解决 → 无效，npm 只认根的 overrides。
2. **误判 2**：以为 `npm install --package-lock-only` 能重生 lock → npm 已知 bug 该模式不完整应用 overrides。
3. **误判 3**：以为跟 node 版本有关 → 无关，esbuild 0.25 的 `engines: >=18` 只是 warning，不产生这个报错。
4. **正确定位**：真正根因是 npm workspaces + 双 esbuild 版本 + optionalDependencies hoist 交互出的 bug。

**修复步骤**:

```bash
# 1. 在根 package.json 的 overrides + resolutions 里加两条
"esbuild": "0.25.5"
"esbuild-loader": "4.4.0"   # 2.21.0 声明 ^0.16.17，冲突；4.4.0 是 ^0.25.0

# 2. 清干净重装（关键！）
rm -rf node_modules packages/*/node_modules package-lock.json
tnpm install --legacy-peer-deps

# 3. 验证
npm ls esbuild   # 只能有一个 0.25.5，无 invalid
```

**关键结论**:

- **install 报错跟你构建哪个 app 无关**：workspaces 是一锅端安装，报错发生在 install 阶段，`build` 命令根本还没跑到
- **要让 overrides 生效必须真实 install 重生 lock**：`--package-lock-only` 是坑，本地不同 npm 版本生成的 lock 跟 CI 也可能不兼容
- **加 esbuild-loader 4.4.0 是消除声明矛盾**：只 override esbuild 会让 esbuild-loader@2.21.0 的 `^0.16.17` 变成非法声明

## 今日总结

一个「install 阶段报错」问题背后是四层原因叠加：npm 允许 postinstall 执行任意脚本、esbuild 用严格版本自检、tea-scripts 双依赖引入两个版本、npm workspaces + optionalDependencies hoist 让平台包错配。

修复的核心不是「猜哪个版本对」，而是**让树里只剩一个版本**。所有采用「JS 壳 + 平台原生二进制」架构的包（esbuild、@swc/core、sharp、lightningcss、@napi-rs/*）在 monorepo 场景都可能踩同款雷，修法通用。

也复盘了几个反直觉的坑：workspace 成员的 overrides 被忽略、`--package-lock-only` 不应用 overrides、本地 npm 版本跟 CI 不同会生成不兼容的 lock。以后遇到 monorepo 依赖问题，第一反应应该是「用 CI 同版本包管理器做真实 install」。
